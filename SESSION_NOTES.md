### Gotchas hit (and fixes) — save the next person the debugging

1. **PowerShell execution policy blocked the scripts** (`running scripts is disabled`). Fix: `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` (git-cloned files aren't MOTW-marked, so RemoteSigned runs them).
2. **`bootstrap.ps1` "context deadline exceeded" is a false alarm.** Helm waits for *all* resources; the demo works before that completes. `otel-collector-agent` sits in **CrashLoopBackOff** (can't reach the central `otel-collector:4318`) but is **non-blocking** for the demo — Prometheus scraping still works.
3. **`start.ps1` background jobs die with their PowerShell session.** If you run it in one window and work in another, `Get-Job` shows nothing and the spawned `uvicorn`/`kubectl` processes can **orphan** — still bound to ports 8765/8080/9090/16686 but broken (symptom: HTTP 500 / health-check timeout). Fix: `Stop-Process -Force` the orphaned PIDs (find via `Get-NetTCPConnection -LocalPort 8765`), then re-run `.\start.ps1` in the window you'll actually use. (Careful: `$PID` is a reserved var — don't name a loop variable `$pid`.)
4. **Dashboard "Inject" button doesn't fire Prometheus alerts** (OTel demo emits `STATUS_CODE_UNSET`, not `ERROR`). Drive the agent chain via `POST /api/triage/fixture/<name>` instead (e.g. `payment_cpu_spike`).
5. **`.env` on this machine holds LIVE credentials** (Azure OpenAI, ServiceNow, Slack, PagerDuty). Don't paste its contents anywhere; keep this folder treated as sensitive.

### Decisions worth remembering

- **Runtime: Rancher Desktop k3s** (not Docker Desktop, not kind). Picked because no Docker is allowed in this org, and Rancher Desktop bundles k3s + kubectl + helm + nerdctl in one install.
- **LLM: Anthropic / OpenAI hosted, NOT Ollama.** 16 GB RAM laptops can't host both the OTel demo (~3.5 GB) and a local LLM (~6+ GB resident). Use the hosted APIs.
- **Skip the OpenSearch sub-chart in the OTel demo Helm values.** Saves ~1.5 GB; we don't use it for Phase 0 (Loki / Tempo via the OTel Collector cover us).
- **Idempotent bootstrap.** `infra/bootstrap.ps1` detects an already-healthy release and skips Helm — avoids the field-manager conflict that bites on re-runs.

### Two gotchas the team should know about (also in `ONBOARDING.md` §7)

1. **Rancher Desktop's `kubectl.exe` is a kuberlr wrapper.** It rejects standard kubectl args (`-n`, `--client`, etc.) when invoked under Python `subprocess` — works fine from PowerShell directly. Symptom: `Error: unknown shorthand flag: 'n' in -n`. Fix: `winget install --scope user --id Kubernetes.kubectl` for a real kubectl alongside it. `inject.py` auto-resolves.
2. **`flagd-config` field-manager poisoning.** Plain `kubectl patch` registers `kubectl-patch` as the field manager; subsequent `helm upgrade` then conflicts. Already fixed in `inject.py` (uses `--field-manager=helm`). Recovery for a poisoned cluster: `kubectl delete configmap flagd-config && helm rollback otel-demo`.
